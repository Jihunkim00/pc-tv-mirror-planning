# 02. 5단계 개발 로드맵

## 공통 원칙

- 각 단계는 독립 브랜치와 PR로 진행한다.
- 각 단계의 완료 조건을 통과하기 전에는 다음 단계로 이동하지 않는다.
- 기능 추가보다 캡처, 연결, 복구 안정성을 우선한다.
- 실제 TV 한 대를 초기 기준 기기로 고정한다.

---

## 단계 1 — 최소 영상 수직 기능

### 목표

Windows 화면이 Android TV에서 보이게 만든다. 화질보다 전체 파이프라인이 동작하는지가 중요하다.

### 범위

- Flutter Windows/Android TV 프로젝트 생성
- 공용 프로토콜 패키지 생성
- Windows 모니터 목록 UI
- Android TV 연결 대기 UI
- Windows.Graphics.Capture로 모니터 캡처
- H.264 720p30 인코딩
- 개발용 고정 IP 또는 단순 로컬 signaling
- Android TV MediaCodec 디코딩 및 SurfaceView 출력
- 시작/중지
- 기본 상태 로그

### 제외

- 오디오
- 자동 검색
- PIN
- 프라이버시 스크린
- TV 전용 오디오
- 적응형 화질

### 완료 조건

- 10분 연속 화면 전송 성공
- 앱 중지 후 다시 시작 가능
- 화면 프레임이 Dart 메모리를 거치지 않음
- TV 뒤로 버튼으로 안전하게 연결 종료
- Windows 앱 종료 시 네이티브 캡처 리소스 해제

---

## 단계 2 — 고화질 영상과 시스템 오디오

### 목표

실사용 가능한 1080p 영상과 TV 오디오를 만든다.

### 범위

- WebRTC PeerConnection 정식 적용
- H.264 1080p30/60 프로필
- D3D11 기반 GPU 경로
- WASAPI loopback 시스템 오디오 캡처
- Opus 오디오 전송
- Android TV 오디오 출력
- A/V sync 측정 및 보정
- PC와 TV 동시 오디오
- 화면만 전송 모드
- FPS, bitrate, RTT, packet loss 진단

### 완료 조건

- 1080p30으로 30분 연속 실행
- 지원 하드웨어에서 1080p60 동작
- 오디오 끊김 없이 TV 출력
- 립싱크가 실사용 가능한 범위
- 화면만 모드에서 TV 오디오가 출력되지 않음
- 세션 종료 후 WASAPI와 인코더 리소스 완전 해제

---

## 단계 3 — 자동 검색, 페어링, 한 번 클릭 연결

### 목표

고정 IP 없이 일반 사용자가 쉽게 연결하게 만든다.

### 범위

- Android NSD 서비스 광고
- Windows mDNS/DNS-SD 탐색
- TV 이름과 기능 capability 표시
- 최초 6자리 PIN 페어링
- 세션 토큰/기기 신뢰 저장
- 최근 TV와 자동 재연결
- IP 직접 연결 fallback
- 연결 상태 사용자 메시지
- Windows 트레이 빠른 연결
- TV 앱 재실행 후 대기 상태 복원

### 완료 조건

- 같은 Wi-Fi에서 5초 내 TV 발견 목표
- 최초 PIN 연결 성공
- 두 번째 연결은 PIN 없이 가능
- 신뢰 해제 기능 동작
- 잘못된 PIN과 만료 PIN 차단
- 다른 PC의 무단 스트림 표시 차단
- 네트워크가 바뀌면 사용자에게 명확한 상태 표시

---

## 단계 4 — 프라이버시 화면과 TV 전용 오디오

### 목표

제품의 핵심 차별 기능을 안전하게 완성한다.

### 범위

- 캡처 제외 네이티브 검은 오버레이
- 첫 프레임 렌더 ACK 이후 프라이버시 활성화
- 전역 긴급 해제 단축키
- 연결 끊김 자동 복구
- crash watchdog 및 다음 실행 복구
- 이전 오디오 장치 저장
- 가상 오디오 장치 또는 검증된 라우팅 방식
- TV 전용 오디오 모드
- 오디오 복구 실패 진단
- 절전/사용자 전환/네트워크 변경 처리

### 완료 조건

- PC 화면은 검지만 TV 영상은 정상
- TV 네트워크를 강제로 끊으면 PC 화면 자동 복원
- Windows 앱 강제 종료 후에도 화면 복원
- TV 전용 모드에서 PC 스피커 무음, TV 소리 정상
- 세션 종료 후 원래 PC 오디오 장치 복원
- 다음 실행에서 미복구 상태 탐지 및 복원
- 긴급 단축키가 Flutter UI 정지 상태에서도 동작

---

## 단계 5 — 제품화, 적응형 품질, 스토어 준비

### 목표

실제 배포 가능한 제품 수준으로 완성한다.

### 범위

- 네트워크 적응형 bitrate/FPS/resolution
- 품질 프리셋: 안정성/균형/고화질
- 자동 재연결 정책
- UI/UX 최종 개선
- reduced motion/transparency/high contrast
- TV 리모컨 포커스 완성
- 진단 로그 내보내기
- Windows installer/MSIX
- Android App Bundle
- 개인정보 처리방침과 권한 설명
- 실제 TV 및 GPU 테스트 매트릭스
- 충돌/메모리/장시간 테스트
- 4K30은 선택적 실험 기능으로만 검토

### 완료 조건

- 2시간 연속 스트리밍 안정성 테스트
- 주요 Android TV 4종 이상 검증
- Intel/AMD/NVIDIA Windows 환경 검증
- 설치/업데이트/제거 검증
- Android TV 리모컨만으로 모든 기능 접근
- 스토어 제출용 아이콘, 배너, 스크린샷, 설명 준비
- 기본 설정에서 안전하지 않은 기능이 자동 활성화되지 않음
